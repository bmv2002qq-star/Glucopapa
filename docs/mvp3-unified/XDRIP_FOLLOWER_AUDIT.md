# Проверка xDrip+ Follower в V1 и V2

20 ноября 2026 года. Аудит рабочей ветки `qa/mvp3-unified-20261120`. Исходники V1 найдены. Официальный исходник xDrip+ проверен на теге `2026.03.01`, коммит `805ba0447cb7288c421cc898640183f8abb042fb`. Версия приложения xDrip+ на телефоне семьи неизвестна.

| Вопрос | Результат |
| --- | --- |
| Как работала V1? | Код Android 0.26 открывал `GET http://127.0.0.1:17580/sgv.json?count=288` через Java. Записывал историю в SQLite и отправлял её в WebView через `window.onGlucoseUpdate`. |
| Как работает V2? | `GFNativeXDrip` читает последнее показание из `content://com.eveningoutpost.dexdrip.contentprovider/bg` с параметром выбора `bg`. `GFProviderCgm` передаёт одну запись в `GFStorage.cgmAdapter`. |
| Совместимы ли способы? | Исходник xDrip+ поддерживает оба механизма и учитывает режим Follower в обоих. Старый HTTP-клиент непосредственно в V2 несовместим с текущими разрешениями. На телефоне совместимость ещё не подтверждена. |
| Что использовать? | Для текущей V2 сохранить ContentProvider. Web Service из V1 имеет преимущество для заполнения пропущенной истории. Рассматривать его для V2 после сопоставления показаний на конкретном Follower и решения о локальном HTTP. |
| Нужны ли правки? | Для аудита требуются только испытания и журнал. Чтобы вернуть Web Service, понадобятся изолированный нативный клиент, разрешение `INTERNET`, узкая политика cleartext для loopback, настройка выбора транспорта и тесты общей дедупликации. |
| Реальный xDrip+ Follower | `NOT_TESTED`. Проверены опубликованные исходники и синтетические контракты. |

## Доказательства по V1

В самом раннем доступном коммите репозитория GlucoPapa 0.26 класс `MainActivity` создаёт `DiaryDb`, регистрирует JS-интерфейс `GlucoBridge` и открывает `file:///android_asset/index.html`. `onResume` начинает опрос через 2 секунды, затем раз в 60 секунд. `onPause` отменяет периодический опрос. Ручное обновление через `GlucoBridge.refreshGlucose()` запускает тот же нативный запрос. Доступ подтверждён исходником Java. Журнал установки и подключения конкретного старого APK к телефону отсутствует. [MainActivity V1](https://github.com/bmv2002qq-star/Glucopapa/blob/ce108bb1972e79e358a876371c6b724218760177/app/src/main/java/ru/family/glucodiary/MainActivity.java#L43-L125) · [Получение данных в WebView V1](https://github.com/bmv2002qq-star/Glucopapa/blob/ce108bb1972e79e358a876371c6b724218760177/app/src/main/assets/index.html#L1831-L1832)

- Клиент устанавливает тайм-аут соединения 4 с и чтения 6 с. Ожидает HTTP 200 и JSON-массив. Берёт `sgv` в мг/дл, `date` в миллисекундах Unix и `direction`. Переводит глюкозу с делителем 18,0182. SQLite заменяет строку с тем же `ts`. Транспорт записывает только общий `lastSync`. У отдельной строки нет времени получения и стабильного ID датчика. [Код SQLite V1](https://github.com/bmv2002qq-star/Glucopapa/blob/ce108bb1972e79e358a876371c6b724218760177/app/src/main/java/ru/family/glucodiary/DiaryDb.java#L141-L156)
- Ошибки HTTP, чтения и разбора сводятся к общему сообщению с предложением проверить Web Service. Старые показания остаются в журнале. Порог сообщения об устаревании равен 10 минутам. Старая таблица допускает метку до двух минут в будущем, а счётчик успешных строк обновляется даже после того, как `addReading` отбросит строку. Этот счётчик нельзя использовать как доказательство сохранения.
- V1 объявляет разрешение `INTERNET` и разрешает cleartext для всего приложения. В xDrip+ требуется включить `xDrip Web Service` (`xdrip_webservice`). По умолчанию `xdrip_webservice_open` выключен, сокет слушает `127.0.0.1`. Локальное чтение работает по тому же пути для Follower. Включение доступа из сети для этого не требуется. [Manifest V1](https://github.com/bmv2002qq-star/Glucopapa/blob/ce108bb1972e79e358a876371c6b724218760177/app/src/main/AndroidManifest.xml#L1-L5) · [Web Service xDrip+](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/webservices/XdripWebService.java#L90-L128) · [Обработка Follower и JSON](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/webservices/WebServiceSgv.java#L120-L193)

## Доказательства по V2

- MVP3 использует `GFNativeXDrip.java`. Компонент проверяет имя пакета, выполняет read-only запрос на отдельном потоке, слушает тайм-аут 5 с и читает `timestamp`, `mgdl`, `delta_name`, `isstale`. upstream `InfoContentProvider` отдаёт последнее `BestGlucose.DisplayGlucose`. `BestGlucose` явно запрашивает показание с учётом Follower. Провайдер для обычной сборки xDrip+ требует включённого `host_content_provider`. `content_provider_write` для V2 не нужен. [V2 Java](https://github.com/bmv2002qq-star/Glucopapa/blob/c091860497d3bae24129ca392c0517be22f653b1/android-mvp3/app/src/main/java/com/glucopapa/shell/GFNativeXDrip.java) · [Поля и опция провайдера xDrip+](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/receiver/InfoContentProvider.java#L87-L117) · [Учет Follower](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/BestGlucose.java#L147-L184) · [Условие доступа](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/receiver/InfoContentProvider.java#L287-L293)
- В V2 сохраняются исходное `mgdl` и переведённое `mmol` с делителем 18,01559, оригинальный `ts`, фактический `receivedAt`, направление из разрешённого перечня или `null`, признак просрочки или `null`. Ключ источника `xdrip-local-provider` означает локальное приложение xDrip+. ID конкретного датчика и цепочка GS1/Juggluco из этого ответа не следуют. [GFProviderCgm](https://github.com/bmv2002qq-star/Glucopapa/blob/c091860497d3bae24129ca392c0517be22f653b1/android-mvp3/app/src/main/assets/www/integration/GFProviderCgm_v0.1.0.js)
- Неподтверждённая свежесть даёт диагностический статус. Показание старше 15 минут или отмеченное просроченным не отображается как текущее. Будущая метка и противоречие значения с уже сохранённым временем отклоняются. Повтор той же метки и мг/дл идемпотентен и сохраняет время первого получения. `GFNativeStorage` пишет snapshot через CAS в SQLite.
- Manifest V2 заявляет видимость ContentProvider, запрещает cleartext и не требует разрешений Android. В GlucoPapa чтение включается отдельной настройкой, опрос идёт только на открытом экране. ContentProvider может кешировать значение до 60 с и отдаёт одну точку. Серия, пропущенная при закрытом приложении, этим API не восполняется. Отключённый провайдер и отсутствующее показание могут выглядеть одинаково для нативного клиента: `NO_MEASUREMENT`. [Manifest V2](https://github.com/bmv2002qq-star/Glucopapa/blob/c091860497d3bae24129ca392c0517be22f653b1/android-mvp3/app/src/main/AndroidManifest.xml#L1-L15)

## Контракт транспорта и дальнейшая проверка

Подключён один потребитель CGM, поэтому включённые одновременно Web Service и ContentProvider в самом xDrip+ не удваивают записи GlucoPapa V2. Если впоследствии потребуется Web Service, перед записью оба ответа должны проходить одну нормализацию и один выбор транспортного источника. На одно время измерения допустим один факт. Совпавшая метка с другим числом требует сравнения происхождения, потому что Web Service целочисленно усекает `sgv`, а ContentProvider передаёт дробные мг/дл. Нельзя заводить второй «сенсор» по имени транспорта или менять уже сохранённое значение при повторе. Для заполнения истории полезно использовать UUID показания Web Service при наличии доказанной совместимости. [Формат Web Service xDrip+](https://github.com/NightscoutFoundation/xDrip/blob/805ba0447cb7288c421cc898640183f8abb042fb/app/src/main/java/com/eveningoutpost/dexdrip/webservices/WebServiceSgv.java#L175-L193)

Синтетические проверки включают MatrixCursor для нативного формата и независимую подачу тестового пакета в действующий браузерный адаптер Android. Тест пакета сравнивает сохранённый snapshot, повтор, конфликт, отказ для будущего времени и восстановление после `force-stop`. Статусы каждого AVD приведены в итоговом отчёте ветки. Проверка на телефоне требует фактической версии xDrip+, совпадения двух ответов с его экраном, восстановления после пропуска и сохранения наблюдений в журнале.

`GFxDrip` относится к исследовательскому прогнозу. Аудит входного транспорта не подтверждает его математический паритет, пригодность для терапии или работу Follower на конкретном телефоне.
