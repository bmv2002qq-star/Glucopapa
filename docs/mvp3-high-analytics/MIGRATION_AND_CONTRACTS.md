# Контракт HIGH и CL‑047

## Хранение настроек

Schema 5 и таблица SQLite используются в прежнем формате. В профиле появились два опциональных поля. Старые записи читаются без записи миграции и без добавления цели. Аудит указывает исходную и новую ревизию, значения и время в ISO 8601.

| Поле | Содержимое при сохранении | Старый профиль |
|---|---|---|
| highTarget | version 1, valueMmol 4–13, source user_input, editedAt | Пустое значение. Отдельный целевой диапазон не становится целью HIGH. |
| highActivity | version 1, enabled, selectedLevel, coefficients, source user_configured, editedAt | В HIGH обычная для low/usual и высокая для high. Флаг включён и отображаются пользовательски утверждённые исследовательские параметры 1,00 / 1,05 / 1,10. |

Локальный выбор HIGH сохраняется через GFSettings в существующий settings‑порт и не изменяет глобальный activityBaseLevel. Выбранный уровень и коэффициенты сохраняются при выключении флага. В расчётном снимке активная спорт-сессия имеет приоритет до фактического конца и не создаётся от выбора в списке HIGH. Пустые или неподходящие данные блокируют расчёт. При OFF используется нейтральный эффект. Отдельные поправки для реальной болезни и спорта остаются открытыми.

## Интерфейс и единственная запись факта

Оригинал HIGH v0.1.3 хранится побайтно. Файл интеграции воспроизводится из него скриптом derive_high_interface.py. Сохраняются CSS и порядок блоков. В разметке интеграции модельные фикстуры и встроенные скрипты сняты. Обычный режим начинается с неизвестных данных и пустой ручной дозы. Изменены подписи состояния для подключённого экрана. CSS и управляющие элементы целевого маршрута проверены на 320/390/428/1280 px.

Iframe не исполняет скрипты. Оболочка работает только с конкретным локальным источником и не принимает команды от iframe. Ввод дозы и расчёт не пишут медицинских фактов. В подтверждении показаны фактическое количество, выбранное место и время. Оболочка сохраняет объект site с region и передаёт событие в actionWriter с ожидаемой ревизией. Повтор того же факта с тем же ID идемпотентен, близкий дубль обнаруживается действующим хранилищем.

Вычисление использует одну ревизию. Входы включают известный источник CGM с временем измерения и приёма, фактический РинФаст, ровно одну пищевую модель, отдельную цель и действующий слот УК/ФЧИ. Источники хранятся в подробностях. Для реального режима допускается только исследовательская базовая траектория на пригодном снимке. Перебор и ручное сравнение доз доступны в изолированном синтетическом журнале. Оригинальный расчёт активности из автономного HIGH там применяется один раз. При активном постпрандиальном вкладе гейт использует CL‑042.1, показывает причину отказа и диапазон GFCOB при доступности. Формулы расчётного ядра сохранены. В active core добавлена проверка отрицательного жира и белка.

## Историческая аналитика CL‑047

Ядро GFInjectionAnalytics v0.2.1 подключено побайтно в собственном пространстве имён. «Места инъекций» по-прежнему обслуживает v0.1.1. Дополнительная панель открывается по уже завершённой еде. Выбор содержит только факты с actualPlate, а расчёт требует одну связную подтверждённую инъекцию РинФаста с сохранённым IOB. Это ретроспективный анализ фактически съеденной порции. Для поиска аналогов подаются записи и CGM, доступные до её временной точки. Обработка срочного действия, предварительный план укола и начало пищевого усвоения имеют другие контракты.

Порты research и injectionAnalytics читаются с проверкой одной ревизии до и после расчёта. Ранее записанные поля болезни не передаются в нормализованный поисковый контекст. История болезни сохраняется для остальных модулей. При неполных данных в минутах остаётся null и появляется причина NO_DATA. GFForecast и RinfastEngine не вызываются как резерв для оценки времени.

Подбор не исправляет старые факты. Текущая отдельная форма подтверждения укола HIGH не привязывает его к приёму пищи. Штатный путь накопления подтверждённой связи и IOB на момент укола ещё нужен. Если связь отсутствует, панель вернёт CONFIRMED_MEAL_INJECTION_REQUIRED. Если есть связь, но отсутствует IOB, результатом будет HISTORICAL_IOB_UNKNOWN.
